    feat(ai): support thinking_token_budget on openai-completions (#7638)
    
    vLLM caps the reasoning phase with a top-level thinking_token_budget. On
    OpenAI-compatible endpoints reasoning and the answer share max_tokens, so a
    reasoning-heavy turn can consume the entire response ceiling and return no
    answer and no tool call — the agent loop then sees a message without tool
    calls and ends the run as if it had finished.
    
    thinkingBudgets from #529 already carries per-level budgets, but only the
    Anthropic and Google paths read it. This wires it into openai-completions
    behind a new opt-in compat flag, and clamps the budget so at least
    MIN_ANSWER_TOKENS remain for the answer.
    
    The flag is independent of thinkingFormat because one vLLM server can serve
    zai, qwen and chat-template models.
    
    Co-authored-by: Ben Shaharizad <ben.shaharizad@taboola.com>

    returning an incomplete response.

    the context window configured in Pi. Its reliability therefore depends on
