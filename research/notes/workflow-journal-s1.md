## Interface decisions and state invariants

The interface method names follow S1. RunHeader requires runId/name/cwd/createdAt/status, with optional serializable inputs. RunSummary is a RunHeader alias. LeaseOutcome is an acquired/held discriminated result; AppendOutcome returns status and the persisted JournalEntry. Returned collections are arrays; read is an AsyncIterable. Only TEXT identifiers (runId, holderId, expectedHolder, key, status, name and cwd) must be well-formed Unicode with no U+0000. No other code points are restricted and no Unicode normalization occurs. Header inputs/event payloads accept every JSON-serializable value, including NUL/lone surrogates as values and object keys. Optional keys distinguish absence from empty; empty keys participate in uniqueness per run. Duplicate createRun preserves the original header, and keyed replay returns the first entry. Sequence starts at 1; empty-tail CAS uses 0; inclusive reads order by seq, never wall-clock time. Lists order by run_id. No cwd normalization or other format restrictions.

Lease states are missing run, unheld run, and held run. Missing-run acquisition/takeover raises RunNotFoundError. Initial acquisition starts epoch 1. Same-holder acquisition retains epoch; another holder receives a held outcome. Takeover requires an exact expected holder and advances epoch. Mismatched takeover returns held, with null holder when unheld. Renew validates holder/epoch without changing epoch. Release validates holder/epoch and retains the row with null holder; reacquisition increments epoch. Append/renew/release reject stale holder or epoch before writes. Lease validation precedes CAS; CAS precedes keyed replay so stale expectations always fail. Missing reads/deletions remain permissive. Deletion removes header/events transactionally and clears the lease holder while retaining the epoch as a durable fencing tombstone. Recreating a run ID is legal and its next acquisition increments the retained epoch, even for the same holder; unrelated runs are unaffected. Close is idempotent; further access raises StorageUnavailableError.

Every database-read seq/epoch must be an integer in 0..Number.MAX_SAFE_INTEGER. Counter queries use node:sqlite bigint reads through typed adapters so out-of-range SQLite integers become JournalCounterRangeError, not a conversion exception wrapped as storage failure. Negative counters use reason negative; non-safe integers (fractions or above-MAX values) use unsafe-integer. The sole counter error carries readonly runId, field (seq or epoch), numeric value, and reason; for a valid current counter whose successor overflows, value is the rejected successor and reason is overflow. Counter and successor checks occur inside the mutation transaction before writes. Zero and safe MAX counters may be read/replayed or renewed/released when no increment is needed; a new seq or epoch above MAX is rejected. No unrelated input normalization or validation is added.

Every caller-supplied TEXT identifier is validated before any SQL, including BEGIN IMMEDIATE or a read query. This includes both lease fields on append/renew/release, expectedHolder on takeover, optional cwd/key filters and StatusChanged.payload.status because it also becomes a TEXT column. JournalInvalidTextError extends JournalError with readonly field: 'runId' | 'holderId' | 'expectedHolder' | 'key' | 'status' | 'name' | 'cwd' and readonly reason: 'nul-character' | 'ill-formed-unicode'. Check NUL first. Validation precedes closed-storage, missing-run, lease, CAS and keyed replay. Read validates upon consumption before its first query. There is no payload/header error field or serialized JSON text guard. Schema names, encoding, bigint checks and null/empty distinctions remain unchanged; no BLOB/CAST decoding path is added.

Metadata initializes transactionally: zero rows inserts the current version; one current row is accepted; one other version raises JournalSchemaVersionError unchanged. At least two rows, even duplicate current versions, raise JournalMetaCorruptError extends JournalError with exact readonly path: string and rowCount: number before other tables or rows change. Failed construction closes its connection and preserves preexisting rows/schema.

Journal contract change: TEXT identifiers additionally reject ill-formed Unicode before SQL, with NUL precedence and the exact seven-field/two-reason JournalInvalidTextError API. JSON remains unrestricted. Metadata must contain exactly one version row after initialization; multiple rows raise JournalMetaCorruptError. No schema names, columns, encoding or version change.

Journal contract change: schema v1 leases.run_id no longer has a cascading foreign key to runs.run_id. Lease rows survive run deletion with null holder_id and their last epoch. This is the smallest durable fencing repair using the specified tables and columns, with no additional counter table, run-ID reuse restriction, migration or legacy path. All exported table, column, event, encoding and version names remain unchanged. The retained tombstones consume one small row per ever-leased run; deleting them would violate fencing.
