# Pi v0.84.1 Port Matrix

This matrix classifies **every one of the 30 commits** in upstream `v0.84.0..v0.84.1` against
Atomic's own `packages/coding-agent` tree. Each row carries the upstream short SHA so the
classification is checkable against the recorded evidence files, plus the Atomic file and line
evidence for the outcome. Sixteen commits touch `packages/coding-agent`; the other fourteen are
upstream package, dependency, release, test-harness, or repository changes. Entries marked **not
yet ported** are open work, not completed reconciliation.

Classification vocabulary — exactly one base classification per commit; `intentionally adapted`
rows also state whether the adapted route is present or open:

| Classification | Meaning |
| --- | --- |
| **ported** | Upstream behaviour now present in Atomic-owned source, adapted only where Atomic's file split requires it. |
| **intentionally adapted** | *(present)* Upstream behaviour is present through a different Atomic mechanism. `present; test pending` means the implementation matches but still lacks the required named regression test. |
| **intentionally adapted** | *(not yet ported)* Atomic has a relevant surface, but the upstream behaviour or Atomic-facing documentation is absent. The row names the required architecture-specific port; this status never claims the behaviour is present. |
| **inherited dependency** | The change lives entirely in `packages/ai`, `packages/tui`, or `packages/agent`, which Atomic consumes as exact-resolved `@earendil-works/pi-*` dependencies; Atomic vendors no copy. |
| **equivalent** | Atomic already had the behaviour before this range; nothing to do, and the row names an existing Atomic test that proves it. |
| **not applicable** | No Atomic counterpart exists: upstream release stamps, upstream-only packages, repository governance, upstream test-harness maintenance, or bookkeeping commits. |

For this matrix, an otherwise matching implementation without that named test remains **intentionally adapted — present; test pending**. It is never **equivalent** until the named test exists.

## Decisions and remaining questions

These rows no longer leave the RemoteSession/engine relationship open:

- **Harness and RemoteSession layering:** `6fb2d76` is present through Atomic's direct Harness factory (`packages/coding-agent/src/server/create-harness.ts`). The experimental `@bastani/atomic/client` surface now coexists with the isolated interactive engine: `RemoteSession` owns upstream `pi-client`/`pi-protocol` transport, leases, snapshots, and transcript projection; the isolated engine owns Atomic's child-process JSONL RPC, rendering, custom UI, and recovery. No bridge or CLI client command connects them.
- **Client/protocol adoption:** the prior-range adoption is resolved on `pi-0.84.1/remote-session-engine`. `RemoteSession.sessions` exposes durable `SessionMetadata` for catalog listing only; consumers that need runtime phase, model, thinking, attachment, or lock state need the acquired `SessionSnapshot`. Revisit this boundary only if upstream supplies an engine-aware/server contract that preserves non-blocking isolated-engine teardown.
- **`AI_AGENT` value:** no row in `v0.84.0..v0.84.1` introduces or changes `AI_AGENT`; the earlier upstream `4f4762f` decision between `pi` and Atomic's branded value is outside this range and is not silently reopened here.
- **Dependency reconciliation:** the five pure **inherited dependency** rows — `171c6b5`, `58fc043`, `fc3554e`, `1532c99`, and `aa601d7` — need dependency adoption before their behavior is available. `a3e93ec` is open rather than inherited because its Atomic-owned docs hunk must land with a future fullscreen renderer. `c03d78b`, `1eb988c`, and the fullscreen route in `c96bfac` also need upstream package adoption plus the stated Atomic work.
