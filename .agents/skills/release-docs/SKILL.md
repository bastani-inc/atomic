# Refresh release docs

Compare the **current checkout** with `packages/coding-agent/docs`. Do not diff a release tag, infer a baseline, or use a commit range to decide what users need. This skill ends at an open docs PR or a no-op; it never merges, tags or publishes.

1. **Preflight.** From the repository root run `bun run scripts/release/release-docs.ts require-non-base-branch`. Require exit 0. It rejects a dirty tree (including untracked files), detached HEAD, and `main`. Record the returned current branch, docs root and PR base (`main`). Do not switch or clean branches for the caller. Create a fresh private scratch directory **outside** the checkout, with an `updates/` subdirectory. Save the preflight JSON as `release-metadata.json`. Keep its path and worker handles in the session so work can resume without repeating a push or a worker edit. Never stage scratch files.

2. **Research before editing.** Start three independent read-only subagents, with fresh context in this checkout, to produce these reports in scratch:

   | Report | Question |
   | --- | --- |
   | `research-code-surface.md` | Which CLI, settings, extension, package and other user/developer behaviors does the current code implement? Cite paths and symbols. |
   | `research-docs-surface.md` | Which hosted docs files own those topics and what do they currently promise? Cite paths. |
   | `research-behavior-gaps.md` | Where is the current guidance missing, stale or misleading? Cite both code and docs. |

   Use codemode to coordinate parallel work: inspect `describeTool("subagent")`, launch the three assignments with `await tools.subagent({tasks: assignments, concurrency: 3})`, save the admitted task IDs with `store`, then call `tools.subagent({action: "wait", id, budgetMs: 30000})` on each. Check for refusals and require settled, successful results or completion notices. A launch is not a result. Use `Promise.allSettled` for independent calls so one failure does not hide the other results. If the installed tool is model-only, use its top-level launch/wait with the same assignments. Collect **all three** nonempty reports before a fresh serial pass synthesizes `current-docs-research.md`. Preserve concrete references and resolve overlap. Workers may write their assigned scratch report only; no repository edits yet.

3. **Plan disjoint edits.** Using the metadata and synthesis, identify actionable stale docs under `packages/coding-agent/docs` only. Follow `AGENTS.md` → Docs: explain how to use, configure or troubleshoot Atomic; not internal implementation or test evidence. Write `detected-tasks.json` in scratch: an array of `{id, title, owner_docs, reason, source_refs, update_instructions, acceptance_criteria}` with repository-relative owner paths, arrays for owners/references/criteria, and other fields strings. Use `[]` for no gaps. Group by owners with:

   ```sh
   bun run scripts/release/release-docs.ts group-tasks "$scratch/current-docs-research.md" "$scratch/detected-tasks.json" > "$scratch/grouped-tasks.json"
   ```

   Stop on nonzero. Read the resulting array. Overlapping owners, including transitive overlaps, are now one task. Check that the actual paths, including any symlinks, stay inside the docs root. For `[]`, write “Validation skipped: no stale docs” to `validation.md`, return `no_changes` with the research and task report paths, and **do not** commit, push or open a PR.

4. **Update docs.** Fan out the grouped tasks with codemode in batches of **at most four** independent subagents. Give each fresh worker its task, metadata, synthesis, the grouped list, its owner files and the scratch output `updates/<key>.md` (`key` is generated by `group-tasks`). Only edit its owner docs. Leave shared navigation/index/cross-link repairs for the serial repair pass. No code, changelogs, manifests, commits, pushes or PRs. Require a report of files changed, evidence and residual risks. Collect every result (do not fail fast or start a second worker on files whose first worker is still running). Run:

   ```sh
   bun run scripts/release/release-docs.ts check-updates "$scratch/grouped-tasks.json" "$scratch/updates"
   ```

   Any missing/empty report, unaccounted-for edit or failed worker means `needs_investigation`; record the evidence in `validation.md` and stop before validation or Git mutations.

5. **Validate and allow one repair.** Use `tools.bash` from codemode to run `bun run scripts/release/release-docs.ts docs-check` from the repository root; save its JSON output to scratch and write its **full** Markdown `summary` to `validation.md`. Inspect the exit code: 0 passed, 2 blocked, 1 error. This runs the hosted docs route/internal-link check, Mintlify syntax validation, and Mintlify broken-link check; all three must pass. If the first pass succeeds, skip repair. Otherwise read the failing command/output, then give **one serial repair** worker the report, metadata, research, grouped tasks and all update reports. It may fix docs, including shared nav/links, only under the docs root. No commits. Record files, commands and risks in `validation-repair.md`, then rerun the **entire** `docs-check` command and append the repair summary and second report to `validation.md`. If unrelated changes would be required, checks still fail, or any result is unknown, return `needs_investigation` with exact evidence. Never publish a PR on partial validation.

6. **Create and verify the PR.** Confirm the original branch is still checked out. Inspect `git status --short --untracked-files=all` and both staged and unstaged diffs. Stop on changes outside the docs root. If no docs changes remain, return `no_changes` with the reports and skip the PR. Otherwise stage only intentional changes under `packages/coding-agent/docs`, review the staged diff, and commit `docs: update release docs`. Push the current branch to `origin` without force; open or update its PR to `main` with that same title. Summarize the branch, research findings (not private artifact paths), grouped task count and validation commands in the PR body. Do not include private evidence, metadata or scratch reports. Never reset, force-push, merge, tag or publish. On an uncertain push/PR outcome inspect the existing branch and PR rather than repeating the operation.

   Save the PR summary in `pr.md` under scratch. Run `bun run scripts/release/release-docs.ts verify-pr "$original_branch"`. It checks the current branch, clean docs tree, and the matching open head/base and URL returned by `gh`. Only exit 0 with `ok: true` warrants `pr_created`; otherwise return `needs_investigation`. Report status, branch, grouped task count, research/validation paths and PR URL or reason it was skipped.
